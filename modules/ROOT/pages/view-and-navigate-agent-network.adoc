= View and Navigate Your Agent Network

Explore an interactive map of agents, brokers, and Model Context Protocol (MCP) servers. Pan and zoom, search and filter by environment or type, toggle layers, and select nodes or edges to view detailed metadata, metrics, and links for deeper investigation.

== Accessing Agent Visualizer

You need these Anypoint Platform permissions to access Agent Visualizer:

* Anypoint Monitoring
* Monitoring: Monitoring Viewer
* Exchange Viewer
* API Manager View: View API Configuration, View Policies

. Log in to Anypoint Platform.
. On the Anypoint Platform home page, click *Open Agent Visualizer*.
+
If you don't see the agent network architecture, it's because there are no discoverable agentic assets in Anypoint Exchange. 

For more information about creating an agent network project and publishing assets to Exchange, see xref:anypoint-code-builder::index.adoc[].

== Navigating the Agent Network

Agent Visualizer provides an interactive view of your agent network where you can:

* Zoom in and out. 
* Click and drag on the canvas to pan the visualization.
* Search for the name of an asset on the canvas to highlight the nodes that contain your search terms.
* Turn on layers to see additional metadata or specific views.
* Filter the graph by design view (as defined in the broker YAML), environment, or agent type (broker, Agentforce agents, external agents, or MCP servers).
* Navigate through interactive elements using the Tab key.
* Navigate between connected and disconnected nodes using arrow keys when the canvas has focus.

== Viewing the Agent Network

When you land on the Agent Visualizer page, you see the agent network map showing all discovered agentic assets nodes and their relationships (edges).

If the page is empty, it means there are no discoverable agentic assets in Anypoint Exchange. For more information about creating an agent network project and publishing assets to Exchange, see xref:anypoint-code-builder::index.adoc[].

=== Viewing Data Flow Layers

Data flow (traffic) layers are used to group nodes in the agent network visualization to show production or nonproduction traffic. Only one type of traffic layer (production or nonproduction) is visible at one time.

By default, the production data flow layer is shown. 

Use the toggle to switch between the default view of production traffic and the view of non-production traffic (development/sandbox traffic).

image::agent-visualizer-layers-toggle.png[Data Flows toggle is turned to view the Production Environments layer]

When the nonproduction data flow layer is active, traffic between nodes in development or sandbox environments is shown as solid edges, and edges representing production traffic disappear. 

== Filtering the Agent Network

You can filter the data set to focus your view.

. Select the filter option.
. Select the filter criteria, such as agent type (broker, internal agents, external agents) or specific platforms (for example, Agentforce).
. Choose an environment view to narrow the graph to nodes deployed in that environment.

== Viewing Node Details

When you select a node, a detail card opens to provide comprehensive information for the asset.

. Select any node in the agent network (or press Enter or Spacebar after focusing the node with arrow keys) to show its detail panel.
. Review the node details.
+
[NOTE]
Broker metadata is defined in the agent network YAML. For more information about creating an agent network project, see xref:anypoint-code-builder::index.adoc[].
+
[%header,cols="30a,70a"]
|===
| Field | Description
| Name | Name of the asset. 
| Description | Description of the asset.
|Provider | Provider of the asset.
| Platform | Platform of the asset, for example, Agentforce or MuleSoft.
| LLM | LLM provider (for example, `OpenAI`).
| Skills | List of skills that are supported by the agent. Skills are concrete, callable operations within a capability, with defined input and output. For example,`lookupOrder`, `createCase`, `updateAddress`.
| Linked Agents | Agents that are linked to the broker. 
|MCP Servers and Tools | List of MCP servers and tools that are connected to the broker.
| Enabled Capabilities | Lists the capabilities that are supportted by the agent. Capabilities are high-level areas of what an agent can do (domains it supports, for example customer support, knowledge search). 
| Instance Name | Instance name as it appears in API Manager.
| Environment Type | Environments the instance is deployed to, for example, `sandbox` or `production`.
| Based on Asset Version | The version of the instance. 
| Policies | Policies that are applied to the instance.
| Governance and Security | Shows whether the asset is protected by a Flex Gateway.
| Performance and Health a| Shows the performance and health metrics for the instance including:

* Successful Requests
+
This metric is shown for brokers, agents, and MCP servers. This is the total number of requests received successfully in the last 24 hours. 
* Failed Request Rate
+
This metric is shown for brokers, agents, and MCP servers. This is the percentage of requests that failed in the last 24 hours. 
* A2A Calls Sent
+
This metric is shown for brokers. This is the total number of messages sent to agents using the Agent2Agent (A2A) protocol in the last 24 hours. 
* MCP Calls Sent
+
This metric is shown for MCP servers. This is the total number of messages sent to  MCP servers in the last 24 hours. 

| Monitoring | Links to logs and traces for quick access to troubleshooting tools. 
| Tags| All tags associated with the asset in Exchange.
|===

[[viewing-edge-details]]
== View Edge Details

When you select an edge, the detail panel displays relationship information and metrics. Metrics are aggregated for all instances that exist between nodes. 

. Select an edge to open its detail panel.
. Examine the metrics:
+
* Source Node ID
* Target Node ID
* Edge type (declared or runtime)
* Call volume 
* Number of conversations (past 24 hours)
* Token consumption
* Policy violations count
* Errors
* Latency
